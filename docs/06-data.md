# 06 資料

> 資料從哪裡來、怎麼正規化、地區價怎麼算、mock 資料長什麼樣。資料表的欄位見 [04](04-architecture.md)。
> 原則：**mock 資料和真實資料走同一條管線**。換成真實資料時，只換「抓取」那一段的 adapter。

## 1. 資料來源

### 1.1 每日資料（本 App 的主要資料）

| 來源 | 國家 | 價格 | 地理單位 | 取得方式 | 狀態 | 用在 |
|---|---|---|---|---|---|---|
| data.gov.in「Current Daily Price of Various Commodities from Various Markets (Mandi)」（Agmarknet 的開放版） | 印度 | 批發：最低、最高、常見價（modal），₹／quintal（1 quintal = 100 kg） | 邦 → 縣 → 市場（APMC mandi） | REST API，需要免費 API 金鑰 | 【查核】曾實際呼叫成功 | B3 |
| 消費者事務部價格監測（DoCA Price Monitoring） | 印度 | 零售與批發，38 種民生品項 | 城市（約 550 個回報中心） | 【待確認】API、下載或網頁 | 只查核到網頁說明 | B4 |
| 農業部「農產品交易行情」（FarmTransData） | 台灣 | 批發：上價、中價、下價、平均價，元／公斤，含交易量 | 批發市場（每個市場屬於一個縣市） | 開放資料 API，不需金鑰 | 【查核】曾實際呼叫成功 | B2 |
| 農業部「農產品物價查報」 | 台灣 | 含零售價 | 【待確認】 | 【待確認】 | 只查到系統存在 | B4 |

- data.gov.in 的 resource id：`9ef84268-d588-465a-a308-a864a43d0070`；台灣的端點：`https://data.moa.gov.tw/Service/OpenData/FromM/FarmTransData.aspx`。查詢參數與欄位名稱**以串接當時的實際回應為準**，寫 adapter 前先存一份真實回應當測試樣本（放在 `backend/tests/fixtures/`）。
- data.gov.in 這份資料**沒有到貨量**。印度改接真實資料後，「到貨量」指標顯示「—」，不自己估算。
- 台灣的交易日期是民國年格式（例：`115.09.19`＝2026-09-19），在 adapter 裡轉成西元日期。

### 1.2 月資料（只用在加分項 B5）

FAO GIEWS FPMA、WFP、FEWS NET、世界銀行 Pink Sheet 都是**月資料**，而且會延遲 1–3 個月，不能當每日行情。B5「國際參考價」只取一條世界銀行具名序列（例如 U.S. HRW 小麥或 Thai 5% 白米），名稱照原文保留，不叫「全球小麥價」，也不和國內價格放在同一張比價表。

## 2. 正規化【決定】

所有來源先轉成同一種**標準報價**，才進資料庫：

| 欄位 | 說明 |
|---|---|
| `country` | `IN`、`TW` |
| `market_id` | 我們自己的市場代號；由來源的市場名稱或代號對照而來 |
| `crop_id` | 我們自己的作物代號（例：`onion`）；由來源的作物名稱、品種對照而來 |
| `trade_date` | 當地的交易日（日期，不含時間） |
| `price_type` | `wholesale`、`retail` |
| `rep_price` | 代表價，**一律換成每公斤、當地幣別** |
| `low_price`、`high_price` | 當日區間（有才存），同樣換成每公斤 |
| `volume_kg` | 交易量或到貨量（有才存） |
| `source`、`fetched_at` | 來源代號、抓取時間 |

- **代表價**：印度用常見價（modal）；台灣用平均價。
- **單位**：資料庫存「每公斤」。印度 ₹／quintal 除以 100。顯示時再依使用者的單位設定換算（見 §5）。
- **對照表**：市場 → 地區、來源作物名稱（加品種）→ 作物代號，存成種子資料（seed），不寫在程式裡。對照不到的資料列丟掉並記數，不猜。
- **同一市場、同一作物、同一天有多筆**（例如不同品種或等級都對照到同一作物）：取這幾筆代表價的中位數。

### 2.1 資料檢查

正規化時做以下檢查；不合格的資料列不進入計算，但記錄筆數（顯示在後端的健康檢查與日誌中）：

| 檢查 | 處理 |
|---|---|
| 價格 ≤ 0、缺代表價 | 丟掉 |
| 最低價 > 最高價 | 丟掉 |
| 代表價不在最低到最高之間 | 保留代表價，區間設為空 |
| 代表價超過同國同作物當天中位數的 5 倍，或低於 1/5 | 視為異常，丟掉 |
| 交易日在未來，或比今天早 60 天以上 | 丟掉 |
| 同一筆資料重複抓到 | 以（來源、市場、作物、品種、交易日）為唯一鍵，後抓到的覆蓋先抓到的 |

## 3. 地區價的算法【決定】

### 3.1 名詞

- **今天**：該國當地時間的日期（印度 UTC+5:30、台灣 UTC+8），由後端計算。前端不自己判斷日期（平台時區不可靠，見 [08](08-platform-constraints.md)）。
- **最新交易日 L**：某地區、某作物、某價格類型，在今天（含）以前最近一個有報價的日期。
- **前一交易日**：L 之前最近一個有報價的日期。

### 3.2 批發

1. 找出地區內每個市場在 L 當天的代表價。
2. **地區批發價＝這些代表價的中位數**；偶數個時取中間兩個的平均。
3. 同時回傳**市場數 n**（L 當天有報價的市場數）。n = 1 時畫面寫「僅 1 個市場」。
4. 地區的最低、最高＝這些市場代表價的最小值與最大值（「本地區 N 個市場」卡片的「最高 X・最低 Y」）。
5. 沒有在 L 當天報價的市場**不列入**中位數。

### 3.3 零售

- 零售以地區為單位：每個地區、每個作物、每天最多一個零售價，沒有市場細項。
- 地區沒有零售回報，或這個作物沒有零售資料時，零售價為空，畫面顯示「尚無零售資料」並說明原因（見 [02](02-product-spec.md) §6）。
- 零售和批發的地理範圍、品級不一定相同，**不計算、不顯示批零價差百分比**；「關於與資料說明」寫明兩者的差額不是中間商的利潤。

### 3.4 漲跌與指標

| 指標 | 算法 |
|---|---|
| 漲跌 | L 的地區價 ÷ 前一交易日的地區價 − 1，同時回傳差額。絕對值 < 0.05% 算持平；顯示時 < 10% 取一位小數（4.2%）、≥ 10% 取整數（12%） |
| 比 7 日均價 | 地區價 ÷（最近 7 個日曆日中有資料那幾天的平均）− 1 |
| 30 日位置 | （地區價 − 30 日最低）÷（30 日最高 − 30 日最低）；最高等於最低時為 0.5 |
| 波動 | 最近 7 天相鄰交易日變動幅度絕對值的平均：< 2% 低、< 4.5% 中、其餘高 |
| 到貨量 | L 的交易量 ÷ 最近 7 個交易日平均交易量：< 0.9 偏少、> 1.1 偏多、其餘一般；沒有交易量資料時為空 |
| 走勢 | 最近 7 或 30 個日曆日，每天一個地區價；沒有資料的日子是 `null`（前端斷線），**不補值** |

- 所有指標都由後端算好再傳給前端，前端只負責顯示。
- 樣本不足（例如 30 天內只有 1 天有資料）時該指標為空，畫面顯示「—」。

### 3.5 資料新舊

| 情況 | 判斷 | 畫面 |
|---|---|---|
| 今天 | L = 今天 | 不另外標示，資訊列顯示資料時間 |
| 休市 | L < 今天，但 L 之後到今天全部是該國的休市日 | 顯示日期，不用警示色 |
| 舊資料 | L < 今天，且中間有非休市日 | 「昨天」「N 天前」；3 天以上用警示色 |
| 無資料 | 30 天內都沒有報價 | 價格「—」、「無資料」，排在清單最後 |

- **資料時間**＝包含這筆資料的那次抓取，完成時的當地時間（例如「9/19 11:40」）。
- 休市日由各國設定（mock：印度週日、台灣週一），真實資料接上後改成「全國當天都沒有報價」才算休市。

## 4. 比價與距離【決定】

- 比價只在同一國家內，列出該國所有地區；每個地區用 §3 的同一套規則算價格。
- **名次**：依價格由高到低排名，同價同名次；沒有資料的地區不排名。名次和使用者選的排序方式無關。
- **差額**：各地區價 − 目前正在看的地區價，單位與畫面一致。
- **距離**：地區中心座標之間的**直線距離**（haversine，地球半徑 6371 km），四捨五入到整數公里。畫面與「關於與資料說明」都寫明是直線距離，不是路程。
- 市場到地區中心的距離存在市場資料中（mock 為固定值；真實資料由市場座標計算，沒有座標就不顯示）。

## 5. 單位與格式【決定】

| 國家 | 價格類型 | 可選單位 | 預設 | 由每公斤換算 | 小數位數 |
|---|---|---|---|---|---|
| 印度 | 批發 | ₹／公擔（quintal）、₹／公斤 | ₹／公擔 | ×100、×1 | 0、1 |
| 印度 | 零售 | ₹／公斤、₹／公擔 | ₹／公斤 | ×1、×100 | 1、0 |
| 台灣 | 批發、零售 | 元／公斤、元／台斤 | 元／公斤 | ×1、×0.6 | 1 |

- 後端回傳每公斤的數值與國家設定；前端依使用者的單位設定換算並用 `Intl.NumberFormat` 格式化。
- 漲跌百分比、名次、市場數不受單位影響。

## 6. 位置推測

- 後端從 `X-Forwarded-For` 取出使用者 IP（信任的代理設定見 [04](04-architecture.md)），用本機的 IP 地理資料庫（預設 DB-IP Lite City，免註冊下載；也可換成 MaxMind GeoLite2 City，需要帳號）查出國家與座標，再找**最近的地區中心**。
- 查不到、國家不在支援清單、或距離最近的地區超過 300 km 時，回傳「推測不到」，前端跳過確認畫面，直接讓使用者選國家。
- 不保存 IP，也不寫進日誌。
- 開發與 demo 時可以用參數指定假的 IP 或直接指定結果（見 [04](04-architecture.md)）。

## 7. Mock 資料規格

### 7.1 原則【決定】

- Mock 產生器輸出的是**來源格式的原始資料**（印度用 data.gov.in 的欄位、台灣用農業部 API 的欄位），經過和真實資料相同的「正規化 → 檢查 → 彙整」才進資料庫。
- 用固定種子的亂數：同一天重跑，數字完全一樣，測試與 demo 都可以重現。
- 日期以「今天（當地）」往回產生 **60 天**，所以任何一天打開 demo 都是「今天有資料」。
- 故意放入各種例外情境，讓每種狀態都能展示（§7.4）。

### 7.2 地區與市場

數值沿用草圖 `ui-mockup/src/data.js` 的 `COUNTRIES`，正式實作搬到後端的 seed 檔：

| 國家 | 地區 | 我的地區預設 | 最近使用預設 |
|---|---|---|---|
| 印度（11 個縣） | Nashik、Pune、Ahmednagar、Jalgaon、Solapur、Indore、Bengaluru Urban、Kolar、North Delhi、Kurnool、Agra | Nashik | Nashik、Pune、Ahmednagar |
| 台灣（10 個縣市） | 台北市、新北市、桃園市、台中市、雲林縣、嘉義市、高雄市、屏東縣、宜蘭縣、花蓮縣 | 台北市 | 台北市、新北市、台中市 |

- 每個地區有：代號、名稱（多語）、所屬的邦或區域、中心座標、**價格水準係數 k**、有沒有零售回報。
- 每個市場有：代號、名稱（多語）、所屬地區、距地區中心公里數、**市場係數 k**。
- Nashik 有 10 個市場（Lasalgaon、Pimpalgaon 等），用來展示「本地區各市場」；其他地區 1–3 個。

### 7.3 作物

每國 10 種，沿用草圖的 `crops`：

| 國家 | 作物 | 預設關注 |
|---|---|---|
| 印度 | 洋蔥、番茄、馬鈴薯、青辣椒、大豆、玉米、小麥、葡萄、香蕉、大蒜 | 前 7 種 |
| 台灣 | 甘藍、小白菜、香蕉、甘藷、青蔥、番茄、芒果、鳳梨、花椰菜、空心菜 | 甘藍、小白菜、香蕉、甘藷、青蔥、花椰菜 |

每種作物有：代號、名稱（多語）、分類、品種說明、今日基準價 `p`（印度 ₹／quintal、台灣元／公斤，seed 時換成每公斤）、當日區間 `lo`／`hi`、與前一交易日的漲跌 `chg`、到貨量 `arr` 與到貨比 `arrR`、**零售係數 `rt`**（`null` 表示這個作物沒有零售資料）。

### 7.4 產生規則

| 項目 | 規則 |
|---|---|
| 市場代表價 | `p × 地區 k × 市場 k × (1 ± 2% 固定亂數)` |
| 市場區間 | 代表價依作物的 `lo`／`hi` 比例展開 |
| 零售價 | `p × rt × 地區 k × (1 ± 2.5% 固定亂數)`；地區沒有零售或 `rt` 為 `null` 時不產生 |
| 歷史走勢 | 今天＝基準價；前一交易日由 `chg` 推回；更早的每天做 ±3.5% 的固定種子隨機漫步 |
| 零售走勢 | 變動幅度是批發的一半 |
| 休市日 | 印度週日、台灣週一不產生任何資料 |
| 到貨量 | 今天 `arr`；前 7 個交易日平均 `arr ÷ arrR` |

**故意放入的例外**（和草圖一致）：

| 情境 | 印度 | 台灣 |
|---|---|---|
| 地區資料是昨天 | Jalgaon | 嘉義市 |
| 地區資料是 3 天前 | Kolar | 宜蘭縣 |
| 地區完全沒有資料 | Kurnool | 花蓮縣 |
| 地區沒有零售回報 | Ahmednagar、Kolar、Kurnool | 雲林縣、屏東縣 |
| 作物沒有零售資料 | 青辣椒、大豆、玉米、葡萄 | 花椰菜、空心菜 |
| 作物資料是昨天／3 天前 | 馬鈴薯／小麥 | 甘藷／空心菜 |
| 地區內有舊資料或無資料的市場 | Nashik 的 Yeola（3 天前）、Malegaon（昨天）、Manmad（無資料） | 台中市的豐原（無資料） |
| 只有 1 個市場 | 多數地區 | 桃園市、雲林縣等 |

### 7.5 Demo 開關（F18）

只在設定 `DEMO_MODE=true` 時生效，正式展示時可以當場切換：

| 開關 | 效果 |
|---|---|
| 模擬 API 失敗 | 價格 API 回傳 503，前端顯示「連線失敗・先顯示 {時間} 的資料」 |
| 模擬地區未更新 | 指定地區的最新交易日往前推 N 天 |
| 模擬推測位置 | 指定 IP 推測的結果（印度 Nashik、台灣台北市、推測不到） |

實作方式見 [04](04-architecture.md)。

## 8. 抓取排程

| 工作 | 時間（當地） | 說明 |
|---|---|---|
| mock 產生 | 啟動時一次、每天 00:05 一次 | 產生到今天為止的資料 |
| 台灣農業部（B2） | 每天 06:00–15:00 每小時 | 當天資料會陸續更新 |
| 印度 data.gov.in（B3） | 每天 08:00–20:00 每小時 | 當天資料會陸續更新；注意 API 金鑰的呼叫次數限制 |

- 每次抓取記錄開始時間、結束時間、筆數、丟掉的筆數、錯誤訊息。前端顯示的「資料時間」來自最近一次成功的抓取。
- 抓取失敗時保留舊資料，下一次排程再試；連續失敗不影響 API 服務。
- 抓完後重新計算受影響日期的地區彙整，API 直接讀彙整表，不在請求時計算。
